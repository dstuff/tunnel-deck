# TunnelDeck

**TunnelDeck — клиент для управления сетевыми подключениями на macOS.**

Приложение объединяет профили OpenConnect, AmneziaWG и Xray в одном интерфейсе.
Оно подключается к указанным пользователем серверам и управляет тем, какой
трафик направлять через подключение, какой — напрямую, а какой — блокировать.
Сервер и параметры доступа пользователь добавляет самостоятельно.

## Возможности

- Сохранение профилей, подключение и переключение между ними.
- Импорт адресов серверов, ссылок VLESS/Trojan, конфигураций Xray JSON
  и файлов AmneziaWG `.conf`, в том числе перетаскиванием файлов в окно.
- Общие правила маршрутизации по доменам, IP-адресам, подсетям и странам IP.
- Три действия для правил: через подключение, напрямую или блокировать.
- Импорт и экспорт схем маршрутизации в формате `.tunneldeck-routing`.
- Проверка настроек, состояние подключения и отдельное окно диагностики.
- Управление из строки меню, в том числе после закрытия главного окна.
- Русский и американский английский интерфейс с мгновенным переключением языка.

## Поддерживаемые подключения

| Тип | Назначение |
| --- | --- |
| OpenConnect / ocserv | Подключение к серверам ocserv с авторизацией по логину и паролю. |
| AmneziaWG 3.1 | Подключение по конфигурации `.conf`, включая параметры маскировки AmneziaWG. |
| Xray | Подключение по ссылкам VLESS/Trojan или JSON-конфигурации, включая REALITY / XTLS Vision. Другие поддерживаемые движком протоколы, например VMess и Shadowsocks, доступны через JSON. |

Приложение использует виртуальный сетевой интерфейс TUN и системную маршрутизацию.
Это позволяет направлять трафик приложений через выбранное подключение без
отдельной настройки прокси в каждом из них. Одна схема правил применяется ко
всем типам подключений: срабатывает первое включённое совпавшее правило,
а при отсутствии совпадений — выбранное действие по умолчанию.
Изменения правил применяются к активному подключению после переподключения.

## Требования

- macOS 14 или новее, Mac с Apple Silicon.
- Для сборки: инструменты командной строки Xcode и Go 1.24 или новее.
  Нужные версии Go toolchain загружаются автоматически при подготовке движков.
- Для подключения: доступ к серверу и разрешение администратора на настройку сети.

Все сетевые движки входят в собранное приложение. Для его использования на другом
Mac не требуется отдельно устанавливать Homebrew, Go или инструменты Xcode.

## Сборка и запуск

Все команды выполняются из каталога `TunnelDeck/`.

При первой сборке подготовьте движки:

```sh
./script/prepare_runtimes.sh
```

Соберите и запустите приложение:

```sh
./script/build_and_run.sh
```

Готовое приложение появится в `dist/TunnelDeck.app`. Для сборки без запуска:

```sh
./script/build_and_run.sh --build-only
```

Для работы над исходниками откройте `Package.swift` в Xcode.

## Использование

1. Добавьте подключение через окно приложения или сочетанием `Cmd-N`.
2. Вставьте адрес сервера, ссылку или конфигурацию и заполните параметры доступа.
3. При необходимости задайте правила в окне «Маршрутизация» (`Opt-Cmd-R`).
4. Подключитесь из строки профиля и подтвердите системный запрос администратора.

Настройки профиля открываются через меню строки или `Cmd-I`,
диагностика — через `Opt-Cmd-L`. Настройки сохраняются автоматически.

В настройках приложения (`Cmd-,`) можно выбрать «Как в системе», «Русский» или
«English (United States)». По умолчанию используется русский, если основной
системный язык — русский; для любого другого языка используется `en-US`.
Дополнительные системные языки не перебираются. Выбор сохраняется отдельно от
профилей и применяется сразу, включая уже накопленные сообщения TunnelDeck в
журнале и копируемый текст. Подключение и незавершённое редактирование сохраняются.
Пользовательские имена и конфигурации, исходный вывод движков и системные форматы
даты/времени не переводятся. Язык системных диалогов определяет macOS.

Проверка конфигурации, успешная авторизация или handshake и подтверждённая
передача данных — разные этапы. Их критерии для каждого типа подключения
описаны в [документации по реализации протоколов](docs/PROTOCOLS.md).

## Устройство приложения

Переводы находятся в `Sources/TunnelLocalization/Resources/ru.lproj` и
`en-US.lproj`: `.strings` содержат тексты, `.stringsdict` — формы множественного
числа. Общий модуль обслуживает UI, TunnelCore и helper. При добавлении текстов
используйте смысловой ключ и параметры; для сохраняемых сообщений используйте
`L10n.message`, для непосредственного отображения — `L10n.text`.

Интерфейс написан на SwiftUI. Процесс `TunnelDeck` управляет профилями и состоянием,
а отдельный `TunnelDeckHelper` с правами администратора настраивает интерфейсы,
маршруты и DNS. Соединения обслуживают встроенные движки OpenConnect,
AmneziaWG и Xray; общий путь обработки трафика обеспечивают Xray и HevSocks5Tunnel.

Данные профилей, включая пароли и исходные конфигурации, сохраняются локально
в `~/Library/Application Support/TunnelDeck/profiles.json`. Каталог доступен
только владельцу (`0700`), файл — для чтения и записи владельцем (`0600`).
Дополнительное шифрование файла и хранение в Связке ключей сейчас не используются.

Текущая сборка предназначена для разработки, имеет локальную подпись ad hoc
и не проходит нотариализацию Apple. Подробности архитектуры, ограничения
и результаты проверок находятся в [docs/PROTOCOLS.md](docs/PROTOCOLS.md),
закреплённые версии и хеши движков — в [Runtime/versions.json](Runtime/versions.json).

## Проверки

```sh
swift test
python3 Tests/Integration/network_configuration_smoke.py
python3 Tests/Integration/routing_smoke.py
python3 Tests/Integration/engine_smoke.py
```

Эти проверки покрывают модели, настройки, маршрутизацию и локальную работу движков.
Они не подтверждают подключение и передачу данных через произвольный удалённый
сервер. Назначение проверок и границы подтверждённых результатов описаны
в [разделе проверок](docs/PROTOCOLS.md#verification).
